# 论文写作分阶段审查（只报告，不改稿）

## 目标与产出

1. **详细审查报告**：`<paper>_writing_audit_<YYYYMMDD>.md`，逐条列出问题、原文、依据、严重度、修改方向。
2. **可选批注 PDF**：若环境中存在 `pdf-review-highlights` skill，按报告生成整句高亮批注文件 `<paper>_annotated.pdf`，形成下游联动。
3. **硬约束：先不动手改论文**。不改 `.tex`、`.docx`，不在报告外偷偷改字。报告只给"修改方向"，不落成新句子全文（除非用于说明拆句结构）。

## 为什么必须分阶段

一次通读同时检查叙事、术语、公式、句式、数字，容易信息过载，结果是每类都看一点、每类都漏。正确做法：

- 一个大步骤只盯 2–4 个小点，整篇扫完；
- 每查完一个小点，立刻把结果写到报告草稿；
- 本步结束后才进入下一步；
- 全部步骤走完后，再按 S6 做两轮复检。

**阶段门（stage gate）**：没有完成当前阶段的"覆盖记录"，不得跳到下一阶段。发现不属于本阶段的问题，先记入 `Backlog`，不展开分析。

---

## 审查流程总览

| 轮次 | 内容 | 目的 |
|---|---|---|
| Round 1 | S1 → S2 → S3 → S4 → S5，逐阶段整篇 | 分点检查，避免过载 |
| Round 2 | S6-1 回读 P0/P1；S6-2 S3 反向全文重扫；S6-3 抽样交叉复核 | 抓漏检与误报 |
| Round 3 | 汇总去重、覆盖矩阵、生成报告、批注联动 | 形成最终产出 |

ID 规则：`S1-01`、`S2-03`、`S3-07`……同一句有多个问题时**合并为一条**，标出主问题，其余作为"附带"。

---

## S1 叙事立场（2 点）

**本步只查这两点，不处理句式与术语。**

- **S1-1 负面结果与试错叙述**
  - 查：`failed`、`did not`、`only`、`unfortunately`、`we were unable`、`attempted`、`first tried`、"先试了……不行"、中间失败、消融失败。
  - 判定：审稿人是否会把它当攻击点？会 → 必须"解决 / 圆场 / 补证据"，不能只在 Limitations 坦白；不会 → 可保留。
- **S1-2 过度道歉、自我削弱、反向改口**
  - 查：`may not`、`might`、`we do not claim`、`remains challenging`、`limitation`、`future work` 中的自我否定；与前文口径相反的软化表述。
  - 判定：合理限定（如适用条件）保留；纯自伤删除或改框架。

产出字段：位置、原句、触发词、审稿人视角判断、处理方向（解决/圆场/补证据/保留）。

---

## S2 文体与数字（3 点）

- **S2-1 实验报告流水账 / changelog 式自白**
  - 查：按时间顺序叙述（`then`、`later`、`after that`、`in this revision`、`we next changed`）、"后来我们又改了"。
- **S2-2 正文 md 式清单堆砌**
  - 查：正文论证中出现分点清单、编号任务条目、时间戳、条目式堆砌；contributions 以外的 itemize。
- **S2-3 数字堆砌**
  - 查：同一句 ≥3 个数字；正文重复表格中的细节数字；关键结论是否只需要 1–2 个数字。
  - 判定：结论句保留少量关键数字，其余交给表/图。

产出：位置、原句、问题类型、建议（改为连贯段落/删数字/移表格）。

---

## S3 句子机械与同义拆句（4 点，2026-11-14 新增）

**这是本 skill 的重点。只查句式机械问题，不查术语与叙事。**

先用候选扫描器（只生成候选，不做判定）：

```bash
python ~/.claude/skills/paper-writing-audit/scripts/scan_sentences.py paper.tex --out sentence_candidates.md --json sentence_candidates.json
```

然后逐节人工复核。**不得只看扫描结果就下结论**，扫描器会漏掉改动过的句子和跨行拆分的句子。

### S3-1 连接词与分号密度

- 一句中 `and` ≥3，或出现分号 `;`，或 `which/while/where/that/who` 等从句标记 ≥3，视为候选。
- 典型坏形态：`A ... and B ..., which ..., and ..., which ...`。
- 分号在一句里原则上不超过 1 个；出现分号说明两个独立判断被硬塞进一句。
- 判定阈值（仅作分诊，不机械套用）：
  - **P0**：≥60 词且含分号，或 `and` ≥4，或两层以上 `which` 嵌套。
  - **P1**：45–60 词且 `and` ≥3，或分号 + 两个以上从句。
  - **P2**：结构尚可、只是偏长的 40–50 词句子。

### S3-2 分句链与主从关系

- 一句 ≥4 个逗号分句，且分句之间没有清楚的因果/转折/条件层次。
- 两个以上独立主张用逗号硬并列（comma splice）。
- `where` 后连续定义 3 个以上符号，且每个定义都带从句。

### S3-3 碎句并列（与长句相反的另一极端）

- 连续 ≥3 句、每句 <14 词，且每句都塞入引用/数字/任务名。
- 处理方向：合并为有主从层次的句子，或保留一句主干、其余降为从句/表格。

### S3-4 同义拆句方案

拆句不是按字数切。对每条候选给出一个**可执行的拆法**，并自检：

1. 找到主断言（main claim）与支撑信息（定义、条件、证据、对比）。
2. 在逻辑边界拆：因果、转折、定义、证据、条件；不在介词短语中间切。
3. 不新增、不删除任何主张或限定条件；不改变数字、引用编号、术语。
4. 每句有明确主语，避免悬空的 `This/It`；必要时重复关键名词。
5. 拆后逻辑层次更清楚；若语气/重点变化，撤销拆法，改用压缩或调整从句。
6. **可接受的长句**：单一主张、层次清楚、无分号、`and` ≤2 的长句保留，不要为短而短。

产出字段（S3 专用）：词数、`and` 次数、分号数、从句标记数、触发类型、拆句方向（用"主句 + 从句/独立句"描述，不重写全文）。

## S4 公式、术语与括号（4 点）

- **S4-1 公式保持纯数学**：公式里大量 `\text{}`、把解释塞进公式；原理说明应在公式外的段落。
- **S4-2 正文散文不内嵌简单数学关系**：`<`、`>`、`≤`、`≥`、`≈`、`\sim`、区间 `[a,b]`、集合 `{x: ...}`、一步能说清的公式（如 SNR 公式、`\eta=0.05`、`BT=0.3`）出现在正文散文里；应改自然语言（"below 6 dB"、"about five percent"）。表格单元可保留简写。
- **S4-3 黑话与未定义缩写**：首次出现的缩写是否展开；领域专有缩写（BS/UE/LOS/LTI/IIR/ERF 等）是否补充全称；一句话是否堆了太多缩写。
  - 例外：通用标准缩写、作为模型名直接使用的缩写，保持裸用，**不要误报**。
- **S4-4 括号装增补信息**：配置细节（`(batch size 20, no gradient checkpointing)`）不应塞括号；有必要则顺进句子，没必要则删或移附录。括号只留给：引用、缩写全写、极短同位语。

产出：位置、原句/公式、问题类型、修改方向（如"改自然语言""移附录"）。

---

## S5 跨节一致性与证据链（4 点）

S1–S4 是逐句检查；S5 是跨段、跨节的一致性检查。

- **S5-1 摘要 / 引言 / 贡献 / 结论口径一致**：同一主张、同一任务集、同一数字范围是否前后一致；贡献顺序是否与引言的问题顺序对应。
- **S5-2 定义、符号、缩写一致**：同一符号是否在不同节含义不同；缩写首次展开后是否又出现未展开的变体；模型名大小写是否统一。
- **S5-3 主张与证据匹配**：每个 `outperforms`、`leads`、`best`、`first`、`state-of-the-art` 是否有表/图/实验支撑；限定条件是否被省略。
- **S5-4 图表与数字一致**：正文引用的表号/图号是否存在；正文数字与表格是否一致；图注与正文描述是否一致。

产出：位置（跨节列出所有出现处）、原文摘录、矛盾点、以哪一处为准的建议。

---

## S6 复检与完整性（3 点，Round 2）

- **S6-1 回读 P0/P1**：逐条回到原文，确认不是误报；确认修改方向没有改变原意；删除证据不足的条目。
- **S6-2 S3 反向重扫**：从结论往引言倒着读，专门找长句/分号/连接过密；再抽样 2 段未标记正文，检查漏检。S3 是漏检率最高的一步，必须二次全文。
- **S6-3 覆盖矩阵与报告完整性**：
  - 每个 section 至少被 S1–S5 各检查一次；缺的补查；
  - 每条 finding 都有位置、原文、规则、严重度、修改方向；
  - 没有"只写问题、不给依据"的条目；
  - 确认论文源文件没有被改动（`git diff` 或文件时间戳）。

## 报告格式

使用 `templates/report_template.md`。核心字段：

| 字段 | 要求 |
|---|---|
| ID | `S3-07`，与阶段对应 |
| 位置 | 节号 + 小标题 + 段落序号；能定位到源文件行号更好 |
| 严重度 | P0 / P1 / P2 |
| 条款 | 如 "戒律 9 / S3-1" |
| 原文 | 英文原句，**必须逐字引用**，不改写 |
| 问题 | 一句话说明触发了什么 |
| 修改方向 | 只写方向与拆句结构，不落成最终改稿 |
| 指标 | S3 条目填词数、and 数、分号数、从句标记数 |

严重度定义：

- **P0**：会给审稿人直接攻击点（自伤叙事、定义堆砌长句、证据与主张不匹配、关键术语未定义）。
- **P1**：明显影响阅读（两层嵌套长句、分号密集、括号塞配置、贡献与引言错位）。
- **P2**：可改可不改的风格问题（轻微数字堆砌、可接受长句的压缩、个别缩写）。

报告开头必须有"执行记录"表（每个阶段覆盖了哪些节、发现多少条），结尾必须有"覆盖矩阵"和"Backlog"。

## 下游联动：生成批注 PDF

先检查当前会话的可用 skills 列表。**若存在 `pdf-review-highlights`，直接调用它**生成批注文件；若不存在，在报告末尾注明"未生成批注"，不要临时造一套标注代码。

推荐执行顺序：

1. 用报告中的 finding 生成批注清单。每条选**首行一小段唯一文本**作为 `--find` 锚点（不要用整句，跨行搜索会失败）。
2. 逐条添加高亮 + 便签：

```bash
python ~/.claude/skills/pdf-review-highlights/scripts/add_review_annotation.py paper.pdf \
  --page 3 --find "The injected update is" \
  --color red --subject "P0 长句/连接过密" \
  --comment "P0 [S3-1] 分号+两个 which 从句，建议按定义/投影/符号拆三句。"
```

3. 全部加完后，补全为整句：

```bash
python ~/.claude/skills/pdf-review-highlights/scripts/complete_sentence_highlights.py paper.pdf
```

4. 验证：高亮组数 = 批注条数；抽查跨行、跨公式、跨栏句；确认正文未改。

颜色与 subject 映射：

| 问题 | 颜色 | subject 示例 |
|---|---|---|
| P0 叙事自伤 / 证据不匹配 / 定义堆砌 | red | `P0 叙事/证据` |
| P1 长句嵌套、括号塞信息、术语问题 | orange | `P1 长句/术语` |
| 分号、and 连接过密（S3-1/S3-2） | brown | `分号/连接过密` |
| 碎句并列（S3-3） | yellow | `碎句信息密度高` |
| P2 风格问题 | amber | `P2 风格` |

注意事项：

- 批注 PDF 必须来自**与报告同一版本**的编译 PDF；源文件与 PDF 不一致时先重新编译，找不到原文的条目跳过并在报告中注明。
- 若 finding 超过 30 条，P0/P1 全标，P2 只标最有代表性的若干条，其余留在报告里，避免 PDF 被涂满。

## 反模式（必须避免）

- 一次通读同时查 8–9 点，最后每类都漏。
- 边查边改论文；或报告里直接给出整段重写稿。
- 只写"这句话太长"，不引原文、不给拆法。
- 把可接受的长句、标准缩写、合理限定误报为问题。
- 拆句时新增或删除主张，改变数字/术语/引用。
- 同一句重复报告多条；应合并成一条，标主问题。
- 未确认 PDF 与源文件版本就生成批注。

## 快速开始

```bash
# 0) 确认源文件与 PDF 版本（必要时重新编译）
# 1) 生成 S3 候选
python ~/.claude/skills/paper-writing-audit/scripts/scan_sentences.py paper.tex --out sentence_candidates.md

# 2) 按 S1 → S2 → S3 → S4 → S5 逐阶段整篇检查，边查边写报告
#    每阶段结束更新"执行记录"；S6 做两轮复检
# 3) 按模板输出最终报告（不改稿）
# 4) 若 pdf-review-highlights 可用，调用它生成批注 PDF
```
