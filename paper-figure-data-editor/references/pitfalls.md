# 踩坑清单（全部来自真实项目）

按"会毁掉多少工作"排序。

## 1. 重画一份图，而不是复用原脚本 —— 最致命

第一版的做法是"读数据 → 自己用 matplotlib 重画一张"。结果是坐标轴刻度、图例位置、线宽、字体、子图比例全都和论文里的图不一样，肉眼一看就知道不是同一张。

**规则**：图只能由原脚本画出来。编辑器的全部作用范围是"脚本里的一个数组变量"。

**自查**：如果 diff 里出现了 `plt.subplots(...)`、`ax.set_*`、颜色定义，说明你走错路了。

## 2. dump 记的是替换之前的值

先 dump 再替换，导出的"原始数据"其实是没被编辑器改过的旧值，看起来像"editor 不生效"。

**规则**：`_record(...)` 必须写在替换之后，记录的是**最终画出去的值**。

## 3. 误差带/CI 在重绘后消失

编辑器里 `err` 是全 0（原图本来就没有误差棒），脚本重绘时按 `err` 画带 → 带没了。

**规则**：`err` 全 0 时不要覆盖，退回使用脚本自己算出的 CI。代码里表现为：
`if not np.any(err_new): err_new = original_err[...]`。

## 4. 改 localStorage 的 key，用户以为数据丢了

加新图时把 `LS = "editor_v6"` 改成 `v7`，旧数据还在浏览器里，但页面读的是 v7 → 一片默认值，用户崩溃。

**规则**：**永远不要 bump key**。合并逻辑本来就是"以缓存为准 + 补上 DEFAULTS 里新增的图"，加新图不需要动 key。
真要迁移，写一段 `if (!v7 && v6) v7 = v6`。

## 5. 替换点对不上，曲线被静默还原

编辑器行是 `"0"`、脚本里 x 是 `0.0`、或者两边浮点写法不同（`0.1` vs `0.10000000000000001`），精确查找失败 → 整条曲线不动，用户以为没保存。

**规则**：按数值匹配并给容差（`abs(x - xv) <= 1e-6`）；匹配不到就**保留原始值并打印一行警告**，不要静默失败。

## 6. 替换后没有排序

编辑器里的行是用户拖动后的顺序，直接拿去 `ax.plot` 会出现回折的锯齿。

**规则**：替换后按 x 升序重排，x 和 y 一起排。

## 7. 非对称误差棒被压成对称

原图是三次重复的 min/max（`[36.0, 47.0]` 围绕 42.0），如果只存一个 `±`，重绘后上下不对称就没了。

**规则**：存 `errlo`/`errhi` 两组偏移量；改数值时保持偏移不变（`lo = v - errlo`），这样误差棒跟着柱子平移而宽度不变。

## 8. 误差棒上下限没跟着新值走

把柱子改到 60，而误差棒还画在旧的 42.0±6.0 上 → 误差棒悬空。

**规则**：重绘时用 `v ± offset` 重新算，不要用存下来的绝对上下限。

## 9. 用字节比对判断"图没变"

matplotlib 的 PDF 内嵌 CreationDate，两次渲染字节必然不同，于是误报"图变了"。

**规则**：比对**像素**（PIL 读成 ndarray 后比 max diff），或只比 PNG。`verify_roundtrip.py` 已经这么做了。

## 10. 一个脚本画多个子图

`only=fig3b` 会重跑整个 `make_figure_main_sweeps.py`，因为六个子图在一个脚本里。这不是 bug，但要在文档里说清楚：同脚本的图会一起重绘。

## 11. 脚本把图写到自己目录，而论文读的是另一个路径

两种情形必须区分：
- 脚本**原地**写到论文用的位置 → 配置里 `"copy": []`；
- 脚本写到 `out/` 而论文读 `figures/` → 配置里写 `"copy": [["out/x.png", "figures/x.png"]]`。

配错的症状：编辑器说"已写入"，论文里的图却没变。

## 12. Windows / Git Bash 的路径

- `FIGDATA_DUMP=/tmp/x.json` 传给 Windows python 会变成 `C:\tmp\x.json`，随后 `open('/tmp/x.json')` 失败；
- 用绝对路径（`E:/proj/_dump.json`）最稳。

## 13. 用 heredoc 写含反斜杠的代码

`cat <<'EOF'` 写 JS/Python 时，`\\` 会被吃掉一层，正则里 `\n` 变成真换行，patch 脚本随后对不上锚点。

**规则**：写补丁脚本用文件写入工具（Write），不要用 shell heredoc。

## 14. 想当然地回写测量文件

"顺手把编辑器里的值写回 measurements.json"是禁区 —— 一旦回写，原始实验数据就没了，"恢复原始"也失去意义。

**规则**：测量文件一律只读；编辑器状态存自己的 `figure_data.json`。

## 15. 两个脚本记录了同一个 chart id

后跑的覆盖先跑的，图上少一条线。`seed.py` 会打印警告，看到就改 id。

## 16. 默认值本身是被改过的

`DEFAULTS`（编辑器里的"原始值"）必须来自**未 override** 的一次运行。如果当初是先改后播种，"恢复原始"恢复的是改过的数。

**规则**：先删除/改空 override 文件再 `seed.py`。

## 17. 图 id 改名

`fig3a` → `snr_v2` 之后，浏览器缓存里旧 id 的改动被合并逻辑丢弃（不认识就删）。

**规则**：id 一旦发布就当契约；要改名就写迁移代码。

## 18. 长脚本把服务器卡住

有的绘图脚本要跑几分钟（读大数据、跑模型）。点一次保存浏览器会转圈，用户以为卡死。

**对策**：先手动计时；超过 ~30 秒的在文档里标注，或提前把数据缓存成小文件。
