# LM 架构瓶颈挖掘与创新发现

## 核心洞察（一切方法的前提）

LLM 架构创新不是"想出一个新结构"，而是跑一场**瓶颈接力**：

> 每篇论文解决上一代的一个具体瓶颈，同时引入一个新瓶颈（往往是它自己造成的）；下一代论文就从这个新瓶颈出发。

因此"发现创新点"= 系统性地定位"当前结构在何处、以何种代价、为何失败"。只要瓶颈描述得足够具体（哪个量、在什么条件下、以什么量级出问题），解决方案的形状基本就被决定了。本 skill 把这套思维路径工程化。

## 工作流

执行任何"找瓶颈/找创新"任务时，按以下五步推进。第 2、3 步分别加载 [references/bottleneck-taxonomy.md](references/bottleneck-taxonomy.md) 与 [references/invention-primitives.md](references/invention-primitives.md) 作为检查清单；第 1 步和写作时加载 [references/case-library.md](references/case-library.md) 获取真实案例的"瓶颈→动作→新瓶颈"样本。

### 第 1 步：确定谱系坐标

- 把目标组件放进它的演进谱系，明确"上一代是谁、解决了什么"。典型谱系见 case-library.md：
  - 残差流：HC → VWN/mHC → AttnRes → xHC（以及 mHC-lite、ANCRe、DDL 等支线）
  - 稀疏注意力：NSA/MoBA → DSA → CSA/HCA、MSA → DoSA/GVR（selector 加速支线）
  - 线性注意力：Linear Transformer → DeltaNet → Gated DeltaNet → KDA → CKDA
  - 优化器：AdamW → Muon → Moonlight-Muon → SAMuon；嵌入：标准嵌入 → 过宽嵌入（VWN）/逐层嵌入（Gemma 3n）/查表式记忆
- 若谱系不明，先检索确认 2-3 篇直接前作，禁止凭空绘制演进图。
- 输出：一句话谱系坐标，如"xHC 是 mHC 在 N>4 扩展受阻后的继任者"。

### 第 2 步：解剖当前前沿的瓶颈

用 bottleneck-taxonomy.md 中的**五类瓶颈来源**逐一检查目标组件，把发现写成如下严格句式：

> 【瓶颈】当【条件/规模】时，【组件 X 的哪个量/哪条性质】导致【可观测的失败或代价，最好带量级】。

要求：
- 瓶颈必须**可归因到具体量**（某个矩阵、某个复杂度项、某个硬编码约束、某个初始化），不允许"效果不够好"这类模糊描述。对照 case-library 里 "residual mixing 成本 O(N³C)"、"PreNorm 稀释使隐状态范数 O(L) 增长"、"indexer 仍需对每个 key 打分" 等范例。
- 优先寻找**上一代方案自身制造的新瓶颈**（mHC 的 Sinkhorn 迭代开销、DSA 的全量打分、AttnRes 的跨 stage 通信）。这是接力的棒，价值最高。
- 区分四类事实强度：论文作者明确声明 > 论文消融/附录数据 > 复现者第三方测量 > 社区推测。写作时必须标注。

### 第 3 步：匹配解决动作原语

瓶颈定位后，到 invention-primitives.md 的**十二条解决动作原语**中匹配候选解法，并检查该原语在 case-library 中的先例与已知代价：

- 参数化（把固定的量放开）→ 例：AttnRes 学残差权重、KDA 逐通道门控
- 约束化（加结构约束恢复性质）→ 例：mHC 双随机流形恢复恒等映射
- 升维/加流（增加并行状态）→ 例：HC 多流残差
- 稀疏化 / 压缩化 / 解耦化 / 混合化 / 缓存复用 / 硬件协同 / 初始化手术 / 数学证书 / 换轴

通常一个好 idea = 一个主原语 + 一个兜底原语（例：MSA = 稀疏化 + 硬件协同 + 初始化手术兜底训练稳定性）。

### 第 4 步：生成并筛选候选假设

每个候选 idea 写成一句可证伪假设，并过五问：
1. 它解决的瓶颈是否已在第 2 步中被具体观测到（哪怕只在分析中）？
2. 成本账：新组件自身的计算/访存/通信是否被算进总账（参考 case-library 中"省 FLOPs 但 top-k 成为新热点"的教训）？
3. 它引入了什么**新瓶颈**？（答不上来通常意味着想得不透）
4. 现有 kernel/并行策略能否低成本承载（drop-in 性）？
5. 能否用 ≤100B token 的 scaling law 在小规模证伪？

### 第 5 步：输出

按下方模板交付分析报告。所有论文级事实必须给 arXiv 编号或明确出处；区分"作者声称"与"第三方测量"。

## 分析报告模板

```markdown
# 【谱系名】瓶颈→创新分析报告

## 1. 谱系一句话坐标
## 2. 逐代解剖（每代一节）
### 2.x 《论文名》(arXiv:xxxx.xxxxx, 时间)
- 上一瓶颈：……（出处/强度）
- 解决动作：……（对应原语编号）
- 关键证据：数字/消融（标注作者声称或第三方测量）
- 新瓶颈：……（谁第一个暴露、在什么规模暴露）
## 3. 瓶颈模式归纳（五类来源中命中了哪些）
## 4. 候选创新假设（按第 4 步五问筛选后的 2-5 个，含可证伪表述）
## 5. 风险与验证计划
```

## 使用纪律

- **不编造论文与数字**：检索不到就写"未找到/待确认"，如案例库中 iHC 一条的标注方式。
- **所有量级数字带出处**：arXiv 编号优先；媒体报道只作线索，不作证据。
- **案例库会过时**：2026 年中以后的新论文需自行检索补入；方法（五类瓶颈、十二原语、五问）不随论文过时。
- 本 skill 只负责"发现瓶颈与构思假设"，实验设计、论文写作分别另属科研设计/写作类技能。
